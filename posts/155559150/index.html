因为主播说自己的项目做的都是后端，所以面试官多数问的是关于后端的问题。

go语言和其他语言的区别

1. 并发模型

  • Go：采用goroutine和channel的CSP（通信顺序进程）模型，轻量级并发
  • Java：基于线程和锁的并发模型，重量级
  • Python：GIL全局解释器锁，限制并发性能

2. 内存管理

  • Go：自动垃圾回收，三色标记法，低延迟
  • C/C++：手动内存管理
  • Java：自动垃圾回收，但GC暂停时间较长

3. 类型系统

  • Go：静态类型，接口隐式实现，结构体组合
  • Java：静态类型，接口显式实现，继承体系
  • Python：动态类型

4. 编译方式

  • Go：静态编译，生成单一可执行文件，无需运行时依赖
  • Java：编译为字节码，需要JVM运行
  • Python：解释执行

5. 错误处理

  • Go：使用error接口，显式错误检查，无异常机制
  • Java：异常处理机制
  • Python：异常处理机制

6. 工具链

  • Go：内置fmt、vet、test等工具，统一的代码风格
  • 其他语言：依赖第三方工具

goroutine的底层原理

1. 基本概念

  • goroutine是Go语言的轻量级线程，由Go运行时调度
  • 占用内存小（约2KB栈空间），启动速度快
  • 支持大量并发（数万goroutine同时运行）

2. GMP调度模型

  • G：Goroutine，包含栈、程序计数器等信息
  • M：Machine，操作系统线程
  • P：Processor，处理器，负责调度G到M上执行
  • 核心思想：将N个goroutine分配到M个操作系统线程上执行

3. 调度策略

  • 工作窃取：空闲P会从其他P的本地队列中窃取goroutine
  • 抢占式调度：防止单个goroutine长时间占用CPU
  • 系统调用处理：当G进行系统调用时，M会与P分离，P会寻找新的M

4. 上下文切换

  • 比线程切换快，因为只需要保存少量寄存器状态
  • 无需进入内核态，在用户态完成切换

5. 实现机制

  • 基于协作式调度，结合抢占式调度
  • 使用M:N调度模型，N个goroutine运行在M个操作系统线程上

什么是slice

1. 基本概念

  • slice是Go语言中的动态数组，长度可变
  • 提供了对数组的抽象，更灵活易用

2. 底层结构

  • 包含三个字段：
    • 指向底层数组的指针
    • 长度（len）：当前元素个数
    • 容量（cap）：底层数组的长度

3. 与数组的区别

  • 数组：长度固定，值类型
  • slice：长度可变，引用类型

4. 扩容机制

  • 当append操作导致长度超过容量时，会触发扩容
  • 扩容策略：
    • 当容量小于1024时，每次扩容为原容量的2倍
    • 当容量大于等于1024时，每次扩容为原容量的1.25倍
    • 扩容会创建新的底层数组，并复制原有元素

5. 常见操作

  • 创建：make([]T, len, cap) 或 []T{1, 2, 3}
  • 初始化示例：
    • 基本初始化：s := []int{1, 2, 3}
    • 使用make：s := make([]int, 3, 5) // 长度为3，容量为5
    • 空切片：s := []int{} 或 s := make([]int, 0)
  • 访问：s[i]
  • 切片：s[low:high]
  • 追加：append(s, v)
  • 复制：copy(dst, src)

6. 注意事项

  • slice是引用类型，多个slice可能指向同一个底层数组
  • 切片操作不会创建新的底层数组，只是创建新的slice结构
  • append操作可能导致底层数组替换，需要注意引用关系

什么是map

1. 基本概念

  • map是Go语言中的关联数组（哈希表），用于存储键值对
  • 提供快速的查找、插入、删除操作，时间复杂度为O(1)
  • 键必须是可比较的类型（如string、int、struct等），值可以是任意类型

2. 底层实现

  • 基于哈希表实现，使用链表解决哈希冲突
  • 包含两个核心结构：
    • hmap：哈希表的头部，包含桶数量、元素数量等信息
    • bmap：桶，存储键值对数据

3. 创建与初始化

  • 声明：var m map[K]V
  • 创建：make(map[K]V, capacity)
  • 字面量：map[K]V{key1: value1, key2: value2}
  • 初始化示例：
    • 基本初始化：m := map[string]int{"a": 1, "b": 2}
    • 使用make：m := make(map[string]int, 10) // 预分配10个元素的容量
    • 空map：m := map[string]int{} 或 m := make(map[string]int)

4. 基本操作

  • 添加/修改：m[key] = value
  • 获取：value := m[key]
  • 获取带存在性检查：value, ok := m[key]
  • 删除：delete(m, key)
  • 遍历：for key, value := range m { ... }
  • 长度：len(m)

5. 特性

  • 引用类型：map是引用类型，传递时不会复制底层数据
  • 零值：未初始化的map为nil，无法直接使用
  • 并发安全：map本身不是并发安全的，多goroutine操作需要加锁
  • 无序性：遍历顺序不固定，每次遍历可能不同

6. 性能优化

  • 预分配容量：创建时指定合适的容量，减少扩容开销
  • 避免频繁扩容：根据实际需求预估容量
  • 合理使用：对于小数据集，slice可能更高效

7. 常见问题

  • nil map：nil map不能添加元素，会导致panic
  • 并发访问：多goroutine同时读写map会导致panic
  • 键类型：键必须是可比较类型，切片、map、函数不能作为键

8. 并发安全方案

  • 互斥锁：使用sync.Mutex保护map
  • 读写锁：使用sync.RWMutex提高并发读性能
  • sync.Map：Go 1.9+提供的并发安全map

播放鉴权实现方案

实现架构：采用前后端分离 + OSS 预签名 URL 方案

具体实现步骤：

1. 前端触发播放流程

  • 用户点击视频播放按钮
  • 前端发送 GET 请求到 /courses/:id/playback/:lessonId 接口
  • 请求头携带 JWT Token 进行身份认证

2. 后端鉴权逻辑

  • Token 验证：通过认证中间件验证 JWT Token 有效性
  • 购买状态检查：查询数据库确认用户是否已购买该课程
  • 权限判断：
    • ✅ 已购买：生成 OSS 预签名 URL
    • ❌ 未购买：返回 403 Permission Denied 错误

3. OSS 预签名 URL 生成

  • 使用阿里云 OSS SDK 生成临时访问链接
  • 设置 3600 秒（1小时）有效期
  • 只授予该视频文件的只读权限

4. 前端播放处理

  • 接收后端返回的预签名 URL
  • 将 URL 传递给视频播放器
  • 播放器使用该临时链接加载视频

5. 安全措施

  • Token 校验：确保只有登录用户才能请求播放
  • 购买状态验证：防止未付费用户访问视频
  • 预签名 URL：临时有效，过期自动失效
  • 禁止下载：播放器设置 controlsList="nodownload"
  • 原始地址保护：OSS 桶设置 Access Denied，直接访问无效

6. 技术实现要点

  • 后端：使用 Go + Gin 实现 API 网关，gRPC 处理业务逻辑
  • 存储：阿里云 OSS 用于视频存储
  • 认证：JWT 实现用户身份验证
  • 性能：预签名 URL 生成轻量，不影响系统性能

优势：安全性高，实现简单，用户体验流畅，适合大规模视频点播场景。
