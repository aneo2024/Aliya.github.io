8. 前端高频面试问答

🔴 React 核心篇

Q1：React Hooks 相比 Class 组件有什么优势？

标准答案：

  1. 代码复用：自定义 Hook 抽离状态逻辑，比 HOC / Render Props 更简洁
  2. 关注点分离：相关逻辑聚在一起，不用散落在各个生命周期
  3. 更少代码：没有 this 指向问题，不用写 constructor 绑定
  4. 类型友好：TypeScript 对函数式组件类型推导更好

我们项目中的应用：

  • useState 管理课程列表、加载状态
  • useEffect 拉取数据、token 变化触发更新
  • 自定义 Hook 可封装课程数据获取逻辑

Q2：虚拟 DOM 的原理是什么？有什么优势？

标准答案：

原理：

  1. 用 JS 对象描述真实 DOM 结构（轻量）
  2. 状态变化时，生成新的 Virtual DOM Tree
  3. Diff 算法对比两棵树的差异
  4. 把差异批量 patch 到真实 DOM

优势：

  1. 减少 DOM 操作：多次变更合并成一次，减少重排重绘
  2. 跨平台：Virtual DOM 可以渲染到 DOM / Native / Canvas
  3. 开发体验：声明式编程，不用手动操作 DOM

我们项目中： 课程列表添加/删除时，React 只更新变化的卡片，不是整个列表重绘

Q3：useEffect 的依赖数组为什么那么重要？

标准答案：

依赖数组决定了 useEffect 什么时候执行：

  • [] 空数组 → 只在 mount 执行一次（componentDidMount）
  • [token] → token 变了才重新执行
  • 不写依赖数组 → 每次 render 都执行

常见坑：

  • 漏加依赖 → 闭包陷阱，读到旧的 state 值
  • 乱加依赖 → 无限循环重渲染

我们项目中的实践： [token] 作为依赖，登录/登出自动刷新购买记录

🟠 性能优化篇

Q4：前端性能优化从哪些方面入手？

标准答案（黄金公式）：

1. 加载时优化（网络层面）

  • 代码分割 Code Splitting → 首屏只加载首页 JS
  • 资源压缩 Gzip / Brotli → 体积减 60%+
  • CDN 分发 → 就近访问，跨运营商
  • 浏览器缓存 → vendor 哈希缓存

2. 运行时优化（渲染层面）

  • 正确的 key → 最小化 DOM 操作
  • 图片懒加载 → 只加载视口内的图片
  • 虚拟列表 → 1000 条数据只渲染 20 条
  • 防抖节流 → 搜索/滚动不频繁触发

3. 用户体验优化

  • 骨架屏/加载动画 → 不让用户看空白
  • 乐观更新 → 点击后立刻反馈，后台慢慢提交

我们项目做了： 代码分割、图片懒加载、分片上传、加载状态反馈

Q5：什么是防抖和节流？什么场景用？

标准答案：

防抖 Debounce： N 秒后执行，期间又触发就重新计时

  • 场景：搜索框输入联想（用户输完才请求，不是每敲一个字就搜）
  • 场景：窗口 resize 结束才计算布局

节流 Throttle： N 秒内最多执行一次

  • 场景：滚动事件（100ms 触发一次，不是每秒 60 次）
  • 场景：按钮重复点击防护（防重复提交）

我们项目可以加：

  • 视频学习进度上报（节流 5 秒上报一次）
  • 课程搜索防抖

🟡 工程化篇

Q6：Vite 为什么比 Webpack 快？

标准答案：

  1. 开发时不打包：利用浏览器原生 ES Module，按需加载
    • Webpack：启动就打包整个项目 → 慢
    • Vite：浏览器请求哪个文件就实时编译哪个 → 秒开
  2. Esbuild 预构建依赖
    • Go 写的 Esbuild，比 JS 写的 Terser 快 10-100 倍
    • node_modules 依赖预先构建，缓存起来
  3. 利用 HTTP 缓存
    • 依赖不常变，强缓存起来，改代码只重新编译业务代码

亲身体验： 我们这个项目，Vite 启动 500ms，Webpack 估计要 10s+

🟢 项目亮点篇

Q7：你这个项目前端有什么技术亮点？

面试官想听的标准答案模板：

“这个在线教育平台，我负责整个前端开发，主要的技术亮点有这几个：

第一，架构设计上：采用 MainLayout 高阶组件模式，所有页面统一导航栏，真正做到了 DRY，改一次导航全平台同步。

第二，性能优化上：

  • 使用 Set 数据结构做 O(1) 购买状态检查，而不是 O(n) 的数组查找
  • 所有课程封面都加了原生懒加载，数据库 ID 作为 React key 最小化重渲染
  • 配合 Vite 做代码分割，vendor 单独打包利用浏览器缓存，第二次访问飞起

第三，视频核心功能：

  • 实现了完整的播放鉴权流程，前端拿到签名 URL 才能播放
  • 分片上传支持大文件，弱网下传坏了只重传 1MB，不是整个 2GB 文件重传

第四，用户体验：统一的错误拦截，网络超时/断网都有友好提示，而不是控制台报错。”

🎯 面试话术模板

面试官：”介绍一下你这个前端项目”

标准回答模板（45 秒版）：

“这是一个在线教育视频平台的前端，我用 React 19 + Vite 开发的，整个技术栈还包括 React Router、Ant Design、Axios，视频播放用的 React Player。

主要做了这些核心功能：

  • 课程广场：轮播图 + 分类导航 + 课程卡片 + 学习数据统计侧边栏
  • 课程详情：视频播放鉴权 + 课时列表
  • 讲师端：课程编辑、视频分片上传
  • 整个项目用了 MainLayout 高阶组件做布局复用，性能上做了图片懒加载、代码分割，网络请求做了统一的超时和弱网提示。”

⚠️ 前端面试避坑提醒

  1. 说的每一个技术点，都要跟上 “在我们项目中…”

    • ❌ 不要只说：”虚拟 DOM 减少 DOM 操作”
    • ✅ 要说：”虚拟 DOM 减少 DOM 操作，比如我们课程列表更新时只重渲染变化的卡片”

  2. 不懂就说”这个场景我当时用了简单的方案，后续可以优化成…”

    • ❌ 不要说：”我不知道”
    • ✅ 要说：”我们项目目前用了最简单的实现，后续规模大了可以用 xxx 优化”

  3. 主动引导面试官到视频播放、分片上传这些亮点

    • 这是这个项目和普通 TodoList 最大的区别！
