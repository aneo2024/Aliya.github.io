一、restful和gRPC接口相关：

gRPC

  1. 什么是 RPC:remote procedure call 远程过程调用
  • 本质：像调用本地函数一样调用远程服务器上的函数
  1. 什么是gRPC：Google开源的现代化高性能RPC框架
  • 核心优势：
    特性 说明
    高性能 基于HTTP/2协议+Protobuf二进制编码
    类型安全 .proto文件定义接口，自动生成强类型的代码
    支持流式通信 四种通信模式
    内置安全 支持TLS\TOKEN\mTLS等认证机制
    自动化 自动生成服务端、客户端代码，减少样板
    跨语言 支持Go、Java、Python、C#等
  1. 底层协议：HTTP/2——gRPC天生适合微服务，实时系统，高并发场景
    相比HTTP/1.1:

  • 高并发不卡顿，支持单链接并发多请求

  • 支持双向流式通信，实现实时通信

  • HPACK压缩，减少请求头大小，提高传输效率

  • 二进制传输，更快，省流量

  1. 数据格式：Protobuf vs JSON
  • 二进制格式，更紧凑，传输效率更高
  • 支持跨语言，无需序列化/反序列化
  • 支持流式传输，实现实时通信
  • 支持批量操作，提高效率
  1. gRPC四大通信模式
类型 描述 使用场景 示例
一元调用（Unary RPC） 客户端调用服务端，一次调用，一次返回 CRUD、查询分数、登录 GetUser()
服务端流（Server Streaming RPC） 客户端发一次请求——>服务端持续推送多个响应 实时推送，日志流 With()
客户端流（Client Streaming RPC） 客户端持续性发送多个请求——>服务端一次返回一个响应 文件文件上传、文件下载 UploadFile()
双向流（Bidirectional Streaming RPC） 客户端和服务端同时发送流式数据，如实时聊天、多人游戏、协作编辑、直播弹幕 实时聊天、实时更新 ChatWith()

restful API

  1. RESTful API的设计：

  • 以资源为中心：资源就是数据，比如用户、文章、订单、商品等

  • 用HTTP方法定义动作：

    方法 动作 幂等性 常见用例
    GET 获取资源 是 获取资源列表
    POST 创建资源 否（多次调用会创建多个资源） 创建新活动
    PUT 更新资源 是 完整替换一个活动的全部信息
    PATCH 部分更新资源 是 仅更新活动的部分信息
    DELETE 删除资源 是 删除活动

  • 清晰定义API输入：

    • 路径参数：用于识别特定资源，是请求所必需的，如
      • GET /events/123

  • 查询参数：对结果进行可选的筛选、排序或者分页

    • GET /events?page=1&limit=10
    • GET /events?page=1&limit=10&sort=created_at&order=desc

  • 请求体参数：创建或更新资源时，发送复杂的数据（通常是JSON格式），如

    • 设计简洁的API响应
    1. 状态码：用于表示操作的结果，比如200表示成功，400表示错误等
    2. 响应体：用于表示操作的结果，比如JSON格式的响应体

二、drawcall

  1. 什么是drawcall
  • 绘制调用，绘制调用是GPU的指令，GPU收到绘制调用后，会根据绘制调用中的参数，将数据从CPU拷贝到GPU，然后进行绘制。
  1. drawcall优化方法
  • 缓存数据：将数据缓存到GPU中，避免每次绘制时都从CPU拷贝数据到GPU。
  • 批量绘制：将多个绘制调用合并为一个绘制调用，减少绘制调用次数，提高效率。
  • 剔除无关数据：剔除无关数据，如剔除掉不重要的数据，如纹理坐标、颜色、法向量等。
