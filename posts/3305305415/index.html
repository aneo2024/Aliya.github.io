五、前端性能优化全景

🎯 优化点 1：DrawCall 减少（Canvas/WebGL 渲染）

什么是 DrawCall？

DrawCall = CPU 给 GPU 发的绘图命令。GPU 画图极快，但 CPU 发命令开销极大。

性能提升：100 倍

标注渲染常用优化手段

技术 适用场景 DrawCall 减少比例
路径合批 同色矩形/线条 100 → 1
实例化渲染 大量重复物体 1000 → 1
离屏 Canvas 静态背景 N → 0
纹理图集 多图标渲染 N → 1

🎯 优化点 2：前端资源压缩

资源类型 压缩手段 Vite 配置 压缩比例
JS/CSS gzip / brotli vite-plugin-compression 70% - 80%
图片 WebP / AVIF vite-plugin-image-optimizer 50% - 70%
图标 SVG 雪碧图 vite-plugin-svg-icons 60% - 90%
字体 字体子集化 font-spider 90%+

🎯 优化点 3：弱网环境专项优化

策略 技术实现 用户体验提升
请求超时重试 fetch-with-retry 指数退避 网络抖动无感知
请求排队 请求队列 + 并发控制 避免雪崩
增量加载 骨架屏 + 内容渐进显示 白屏时间 → 0
图片降级 WebP → JPG → 低分辨率 极端环境可用
离线缓存 Service Worker + Cache API 二次打开秒开

六、面试话术锦囊

Vue 架构相关

“这个项目我采用了 Vue 3 Composition API + Pinia 的组合，做了比较清晰的分层。ChatView 做业务编排，各个子组件只做单一职责，比如 ChatInput 就只管输入和文件上传，通过 emit 把结果抛给父组件。状态都抽到 Pinia 里，这样组件之间的通信就干净了。

流式输出这块我做了很多用户体验优化。最关键的就是乐观更新，用户发消息我不等接口返回，立刻把消息加到聊天列表里，感知上就快了很多。”

性能优化深度版

“前端性能优化我是分几个维度做的：

首先是渲染层面，Canvas 画标注框的时候，把几百次 strokeRect 合并成一次 stroke，DrawCall 直接降两个数量级；
然后是资源层面，构建时做代码分割、gzip、WebP 转码，首屏包体减了一半多；
最后是弱网专项，做了一个请求队列，并发数控制，加指数退避重试，弱网下用户感知就很顺滑了。”

面试官拷问应答

❓ 问：”Pinia 和 Vuex 区别是什么？为什么不用 Vuex？”

✅ 答：”Pinia 是 Vue 官方现在主推的。主要区别就是去掉了 Mutation 这一层，直接 Action 修改状态，TypeScript 支持也更好。而且 DevTools 支持时光机调试，开发体验确实好很多。”

❓ 问：”SSE 流式为什么不用 WebSocket？”

✅ 答：”就这个场景来说，就是服务器单向推状态，SSE 足够了。EventSource 浏览器还帮你自动重连，开发量小。WebSocket 主要是需要客户端也发消息的时候才用，比如要做用户中途点’停止生成’，那我就会上 WebSocket 了。”
